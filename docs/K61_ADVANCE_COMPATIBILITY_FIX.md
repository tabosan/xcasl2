# K61_advance.cas の異常終了の調査と修正

更新: 2026-10-27。

## 結論

原因はxCASL2のNOPに対するレジスタ検査。`#000A`を元WCASL2はNOPとして実行するが、移植版は未使用のxフィールド`A`を不正レジスタとして拒否していた。元のCASファイルの変更は不要で、CPU実装を修正した。アセンブラとリンク処理は変更していない。

対象: `C:/Users/tabos/デスクトップ/Dev Softwares/wcasl2/K61_advance.cas`、2721バイト。
SHA-256: `d89b2ff90dbeadee6a0ae6885778f0e1c3cff1d3ef5a10e8b23f0e28c978e962`。
調査後も同じハッシュで、元ファイルは変更していない。

## 再現

0020配置・FFFF初期化でアセンブルし、命令粒度で実行すると9命令目で停止した。

| 項目 | 修正前 |
|---|---|
| メッセージ | 不正なレジスタ指定: #000A |
| 命令先頭 | #0088 |
| 停止時PR | #0089 |
| IR1 | #000A |
| デコード | opcode=00、r=0、x=A |
| ソース位置 | 64行目 `C10 DC 10` |

14行目の`CALL ITOSTR`は#0096の`C0 DC 0`へ入り、これをNOPとして通過する。続く89行目の`CALL DIV10`は#0088へ入り、`C10 DC 10`を取出していた。`DIV10 START SUB2`の直後にデータがあるため、呼出し直後にこのデータを命令として実行する。

当初はSTARTの開始ラベル指定を呼出先へ反映する問題を疑ったが、元EXEのアセンブラ／リンカを動かして比較したところ、開始番地と**全3000語の配置メモリが一致**した。原版もCALLの機械語に#0088を書き込む。副プログラムの開始ラベルへCALLを差し替える修正は行わない。

## 元版の動作

原版のopcodeディスパッチは上位8ビットでNOPを選び、NOPのr/xビットをレジスタとして使用しない。従って`#0000`だけでなく`#000A`もNOPとして通過し、次の#0089の`SUB2 LAD GR3,0`から処理を続ける。`DC 10`を実行することが、今回のプログラムで直ちに異常終了を意味するわけではない。

原版の1命令STEPはNOPでもアドレス生成を経由する。x=Aでは、原CCPUの配列外参照が隣接するPRに当たり、未使用の実効アドレスが`#0088 + #0089 = #0111`になる。この値はNOPの処理には使われない。

## 修正

- `machine.rs`: opcode=00の直接実行はr/x検査・GR参照をせずNOPとして完了する。
- `pipeline.rs`: NOPをレジスタ指定の検査対象から外す。命令／フェーズ／最小STEPすべてに適用する。
- 1命令STEPで観測される未使用EAも、原版のCCPUレイアウトを値の対応表で再現する。x=8〜CはSP・FR・PR・IR1・IR2、Dは固定対象のパディング0、E/Fは原EXEのCDecoder vtable値の下位／上位ワード。Rustの配列外アクセスや、ホストのポインター参照は行わない。固定値は対象ハッシュのEXEに基づく（`00409684`、`0040C9DC`）。
- LD等の実際にレジスタを使う命令での不正r/xは、従来どおり安全に停止する。

## 検証結果

元EXEのx86ルーチンをUnicornで実行した期待値と修正版を照合した。MFC画面の比較ではなく、元EXEのアセンブル／リンク／CPU／ディスプレイ処理の比較。

| 確認項目 | 結果 |
|---|---|
| アセンブル後のメモリ | 全3000語一致 |
| 完了命令数 | 両方3379 |
| 終了 | トップレベルRETで正常終了 |
| 出力 | `1`, `1`, `2`, `6`, `24`, `120`, `720`, `5040` |
| 最終CPU | GR全8本、PR、SP、FR、IR、MAR、MDR、EA、デコーダ、CALL深さが一致 |
| 実行後のメモリ | 全3000語一致 |
| STEP粒度 | 命令・フェーズ・最小STEPすべて完走し、最終CPU・メモリ・出力が一致 |

追加5テストで、原版NOPの36トレース、全256種類のNOPワード×3粒度、不正レジスタの安全停止、DC 10を先頭に置く最小サブルーチンと戻り、元版でリンクしたK61の全実行を検証した。既存の比較も含め、`cargo test --workspace --locked --offline` の40テストが通過。Clippy、fmt、埋込みTauri EXEのビルドも成功した。成果物は`target/debug/xcasl2-desktop.exe`。

## 調査データと再実行

`analysis/results/k61-compatibility/` に次を保存。

- `before.json` / `after.json`: 修正前後の実行状態と直前24命令のトレース。
- `original_build.json` / `original_execution.json`: 元EXEから取得した配置と3379命令の実行結果。
- `start_export_cases.json`: START仮説の確認用7ケース。呼出先を再配置しないことを確認。
- `nop_padding_cases.json`: NOPの36トレース。移植版で作った期待値ではない。
- `comparison.json`: 配置・最終CPU・全メモリ・出力・命令数の比較結果。

Rustの読取り専用診断コマンド:

```powershell
cargo run -p xcasl2-core --example diagnose -- 'C:/Users/tabos/デスクトップ/Dev Softwares/wcasl2/K61_advance.cas'
```

元EXEの再観測は`analysis/probe_start_exports.py`と`analysis/probe_nop_padding.py`を使う。省略可能な第1引数にCP932のCASファイルを指定する。元ファイルへの書込みは行わない。
