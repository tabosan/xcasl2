# COMETモードのCPU図とメモリ・ソース表示

更新: 2026-10-30。

画像の構成に合わせ、左上にCPUブロック図、左下にディスプレイ／ファイル出力とキーボード入力、右側に1語ごとのメモリと対応ソースを配置する。CASLのレジスタ・ラベル・スタック配置は維持する。ライト・ダークの両方に対応する。

## CPUブロック図

IRの2語とDecoder／Controllerを左、PR・SPとGR0〜7の縦並びを中央、MAR・Adder・実効アドレスEA・MDR・ALUとFRを右に置く。折れ線のバスと矢印で接続する。SVGで描くため拡大しても文字や配線がぼやけない。図は最小430px幅を確保し、狭い欄では個別にスクロールできる。

IR、PR、SP、全GR、MAR、MDR、EA、FR、デコーダのopcode／r／x／adrには実行状態の値を使う。r・xは4ビット、FRはOSZの3ビット、それ以外のレジスタは16進。Controllerには現在のフェーズと最小STEPを示す。ALUは演算器の形状で表し、保存されていない演算結果やラッチを合成しない。Adderの出力はコアの実効アドレス。

コアの直前の転送情報を使ってブロックと経路を強調する。アドレス生成に使ったALUは図上ではAdderの経路に対応させる。GRのr／x指定と、直前の値から変わったGRも区別する。全制御線の電気的状態や原版の点灯条件の完全再現は対象外。

## メモリとソース

右側の「番地／値／ソース」は物理メモリ1語につき1行。2語命令やIN／OUTマクロの展開語も表示し、対応ソースは先頭語の行へ置く。値は現在のメモリから読み、書込みで変わった語を強調する。ソースに対応する行のクリックで編集タブの定義行へ移動できる。

現在の命令、PRが指す語、MARが指す語を区別して表示する。「PR追従」は現在の命令を含む128語の窓を選び、現在行をスクロール範囲へ入れる。追従をオフにすると現在の窓を固定する。先頭番地の入力（0000〜0BB7）でも固定できる。物理終端では残る語だけ表示し、範囲外の値は合成しない。

追従状態はタブごとに保持し、新しいシミュレーターは追従オン。手動指定の先頭番地は従来のメモリ表示設定として保存する。複数の図を同時に開いてもSVGとフォームのIDを分離する。

## 検証

`tests/comet.test.mjs`は実レジスタ値・IRの2語・FR・デコーダ、アドレス生成と通常のALU経路の区別、不正レジスタ番号、メモリとマクロソースの語単位対応、現在命令の判定、物理境界、複数SVGのID分離を検証する。

フロントエンド36本、TypeScript/Vite、Tauri埋込みEXEビルドを通過。Windows実画面でライト／ダークのCPU図、最小STEPでのMAR・MDR・IR更新と経路強調、手動番地・ソース行への移動・PR追従の再開を確認した。Helloサンプルは128最小STEP／10命令で正常終了し、左下の出力とCASL切替後の状態保持も確認した。記録: `analysis/results/comet-layout/gui-verification.json`。
