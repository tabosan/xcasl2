# エディターのシンタックスハイライト

更新: 2026-10-27。

CASL IIソースの入力・読込・サンプル切替・cmk内の編集ファイル切替に合わせて色分けする。常時有効で、設定変更は不要。

| 対象 | 表示色 |
|---|---|
| 機械語命令 | 緑 |
| START / END / DS / DC、IN / OUT / RPUSH / RPOP | 紫 |
| GR0〜GR7 | 黄橙 |
| ラベル定義・参照 | 青 |
| 10進・16進の数値 | 桃 |
| 文字列 | 黄緑 |
| コメント | 灰青 |

`src/highlight.ts` は行のラベル欄・命令欄・オペランド欄を区別する。命令と同じ綴りのラベルも位置に応じて着色する。日本語文字列、引用符の二重化、`=`によるリテラル、編集中の閉じていない文字列を扱う。原版の前処理と同じく、文字列内でも最初の`;`以降をコメントとして表示する。小文字の命令は認識しない。色分けは入力補助であり、構文・名前解決・値の範囲の検査はアセンブラが行う。

編集面は従来のtextareaを保持し、その下のpreに色付き表示を重ねる。ソース本文を書き換えないため、ネイティブのキャレット、範囲選択、コピー、通常入力のUndoを使える。グループ移動でWebViewの標準Undoが失われる場合は、ファイル別の補助履歴を使用する。[分割とドラッグ移動](SPLIT_TABS.md)を参照。表示レイヤーはポインター操作とアクセシビリティの対象から除外し、ソースを二重に読み上げない。色以外のフォント寸法を揃え、タブ幅は4。

スクロール時は縦横のオフセットを同期し、表示サイズはtextareaのスクロールバーを除く領域に合わせる。行番号も同期する。末尾の空行が潰れないよう、表示だけに幅0の番兵を置く。Windowsの強制カラーではtextareaの通常文字表示に戻す。

## 検証

`npm run test:editor` で6本のテストが通過。実行にはNode.js 22のTypeScript型除去機能を利用する。

- 命令欄とラベル欄、マクロ、レジスタ、数値、リテラル。
- 日本語、引用符の二重化、編集中の文字列、文字列内のコメント開始。
- HTML記号を含むソースのエスケープと文字の保持。
- 空行・末尾改行・2000行の文書。

TypeScriptの型検査、Vite、フロントエンドを埋め込んだTauri EXEのビルドも通過。

Windows実画面ではHelloの色分け、アセンブル成功、配置表クリックによるソース行選択、`1`→`19`のキー入力への追従、Ctrl+Zによる復元を確認した。`analysis/results/implementation-highlight/scroll.cas` は日本語・引用符・タブ・長いコメントを含む100行の検証用ソース。これをCP932で開き、Ctrl+Endによる最終空行への移動、長い行のEndによる右端への移動で、表示・行番号・キャレットの位置を確認した。検証記録は同フォルダーの`gui-verification.json`。
