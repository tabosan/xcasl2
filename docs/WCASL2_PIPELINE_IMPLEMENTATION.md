# COMETパイプラインの実装と照合

2026-10-27。対象は元仕様書と同じSHA-256の `Wcasl2.exe`。Rust実装は `crates/xcasl2-core/src/pipeline.rs`。

## 追加採取

`analysis/probe_pipeline_port.py` は元EXEのルーチンをUnicornで実行する。Rustコアから期待値を作っていない。

- 38機械語形式。
- JMI〜JOVの全FR組合せ48条件。
- トップレベルRET、未知opcode、IR2を保持する連続命令、番地2999での2語取出、指標加算の16bit折返し、SP=0/FFFF、シフト量0、IN、OUTの12条件。
- 以上98条件に対し、最小STEP、フェーズSTEP、命令STEPを採取。294トレース・1790遷移。

取出から命令完了／停止までのGR、PR、SP、FR、IR、MAR、MDR、実効アドレス、デコーダ、フェーズ、フェーズ内STEP、CALL深さ、関連メモリ9番地、ディスプレイ12行を `analysis/results/pipeline_port_cases.json` に保存した。INはダイアログから「あｱ」が返る部分だけをホストで模擬し、その後の原ルーチンの書込を採取している。

既存の `pipeline_cases.json` 11トレースも別のRustテストで引き続き照合する。

## 原版の転送規則

| フェーズ | 原版ルーチン | 主な処理 |
|---|---|---|
| 取出（0） | 0040C600 | 1語につき4 STEP。MAR←PR、バス選択、MDR←Memory[MAR]・PR加算、IR←MDR |
| 解読（1） | 0040C7D0 | 第1 STEPでopcode/r/x/adrへ転送、第2 STEPで次フェーズへ |
| アドレス生成（2） | 0040C990 | 入力選択、16bitのadr＋指標GRを実効アドレスへ |
| 実行（3） | 0040CA90 / 0040CB50以下 | 命令ごとのメモリ転送、演算、書込、終了判定 |

### 粒度による違い

最小STEP／フェーズSTEPの分岐 `0040C410` は、1語命令ではアドレス生成を省略し、フェーズ2から実行ルーチンの第1 STEPを同じ呼出しで進める。フェーズSTEPの場合はその実行フェーズを最後まで進める。

命令STEPのループ `0040C480` は、1語命令でもアドレス生成ルーチンを通す。IR第2語は1語命令の取出で消去されないので、前の値とxフィールドのGRを使って実効アドレスが更新される。例:

```casl
MAIN START
 LAD GR1,7
 LD GR1,GR2
 NOP
 RET
 END
```

GR2=1234なら、LD実行後の実効アドレスは最小／フェーズSTEPで0007、命令STEPで123Bとなる。GR1へ入る値はどちらも1234。一般的な命令シミュレータで見えない差分も、COMETの状態として保持する。

### 実行フェーズ

- メモリLDはMAR設定、バス選択、MDR読込の後でGRとFRを更新。
- レジスタLDは実行の第1 STEPでFR、第2 STEPでGRを更新。
- メモリ演算・論理・比較はMDR読込の後に制御STEPを挟み、最後に演算をコミット。MDRに保持した値を使い、コミット時に再びメモリを読まない。
- STはMARとMDRの設定後、書込STEPで初めてメモリを変更。
- PUSH/CALLはSP減算、アドレス・データ転送、メモリ書込、分岐を個別のSTEPとして処理。
- POP/内部RETはMARへ旧SPを移し、SPを増やしてからMDRを読込み、最後にGR／PRへ移す。
- トップレベルRETと未知opcodeはフェーズFFFFFFFFへ移る。通常の命令完了は0/0へ戻る。
- SVC 1/2はサービス本体を1回呼んで命令を完了。未知SVCは実行0〜10を経て状態を保持したまま完了する。

## Rustセッション

`Machine::step_mode` に `Instruction` / `Phase` / `Micro` を指定する。`Machine::step` は命令粒度の互換APIとして残す。途中で粒度を変えた場合は現在位置から進める。

`Session` のSTEP回数と、コアの完了命令数・内部最小処理数は別に保持する。戻りは原版の `0040D260` と同じく、現在の粒度でSTEP回数−1までリセット後に再実行する。粒度変更の履歴を遡るUndoではない。

INでは入力待ちイベントを返し、入力確定でメモリへ書く。入力待ちの間にCPU STEPを余分に進めない。戻りの再実行でも入力を求め直す。長い再実行は最大1000 STEPずつに分割し、GUIの停止操作を可能にする。

## UI

右上のSTEP選択で命令／フェーズ／最小STEPを切り替える。フェーズまたは最小STEPを選ぶとCOMET表示に切り替わる。CASL / COMETの表示切替とSTEP粒度は別の選択として扱う。

COMET図はコアの実値を表示し、直前のSTEPに関係する部分を強調する。「次: フェーズ / STEP」は次に進める内部位置、転送文は直前に行った処理を表す。ALUの「16 bit」は機能表示であり、原版に存在しない仮想レジスタの値を表示するものではない。

既存のレジスタ欄・メモリ・入力／出力も同じCPUとメモリを参照する。命令取出でPRが増えても、CASL行の強調は現在の命令先頭を使う。

図の配線・色・制御信号の点灯全ビットは新UIの表現であり、原COMET画面の完全な画面互換は未照合。レジスタを使う命令の不正r/xによるメモリ破壊は再現せず停止する。NOPの未使用ビットは許容し、原版のNOP追加36トレースを照合した（[K61の修正](K61_ADVANCE_COMPATIBILITY_FIX.md)）。指定アドレス停止は未実装。cmkは追加実装済み。[ファイル装置I/O](WCASL2_FILE_DEVICES_IMPLEMENTATION.md)は追加実装済み。

## Windows実画面での確認

Tauriの最小STEPで1回目のPR→MAR、2回目のアドレスバス選択、3回目のMemory→MDRとPR加算を確認した。3回目からBackspaceすると、PR=0020・取出STEP2へ戻った。

フェーズ粒度ではLAD GR1,1について、取出8内部STEP→解読まで10→アドレス生成まで12→実行完了13を確認。4回の操作でGR1=0001、完了命令数1となった。そこからBackspaceすると3操作・12内部STEP・実行STEP0・GR1=FFFFへ戻り、アドレス生成の結果は0001を保持した。

TypeScriptビルド、Windows Tauriビルド、Rustの15テスト、コアのClippy確認を通した。既存の1578ケースに加え、パイプライン305トレースとセッションの追加試験を継続的に照合する。
