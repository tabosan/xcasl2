# ファイル入出力装置の実装

2026-10-27。対象は既存のハッシュで固定したWCASL2。原版の観測事実は[実ファイル解析](WCASL2_NATIVE_IO_AND_PATHS.md)、本書は移植版の実装状況。

## 操作

ツールバーの「入出力装置」で、入力をキーボード／ファイル、出力をディスプレイ／ファイルから個別に選ぶ。ファイルダイアログで選ぶか、パスを直接入力できる。

「適用してリロード」は、既存のストリームを閉じてCPUをロードし直す。設定しただけでは入力を読まず、出力先も作成・切詰めしない。ファイルは最初のIN／長さが0でないOUTで開く。設定は同じアプリ内の新規アセンブル・サンプル切替でも保持し、アプリ再起動時にも復元する（[設定の永続化](WCASL2_PROJECT_SETTINGS_IMPLEMENTATION.md)）。

サンプル「ファイル入出力」、または `examples/file-records.cas` は、EOFまでIN→OUTを繰り返す。末尾空白の除去とCRLF付加を伴うレコード処理であり、バイナリをそのまま複製するサンプルではない。空レコードはLEN=0となり、ファイルOUTが何も出さない原版の規則に従う。

ファイル出力中は画面にパス、出力レコード数、変換後バイト数、バッファ内バイト数を表示する。画面OUTへの同時転送は行わない。

## コアの分担

| 場所 | 役割 |
|---|---|
| `crates/xcasl2-core/src/devices.rs` | レコード変換、遅延Open、ファイル位置、バッファ、Close、同一ファイル検査 |
| `machine.rs` | INの入力要求とメモリ書込、OUTの下位8bit取得・ファイル向け出力要求 |
| `session.rs` | 各STEPのI/O要求を処理し、終了・再実行・リロードでストリームを閉じる |
| `src-tauri/src/main.rs` | 装置設定の保持、パス選択、編集中ソースへの出力禁止、終了前Close |
| `src/devices.ts` | 設定ダイアログ、パス選択、適用とリロード |

ファイルハンドルをCPUのスナップショットへ含めない。再実行で入力を先頭から読み、OUTへ再到達した時点で出力先を作り直す。I/Oを含むTauriコマンドは非同期コマンドとしてGUIスレッドから分けて実行する。

## 入力

- バイト列をそのまま1語へゼロ拡張する。データをUTF-8へ変換して再エンコードしない。
- CRLF/LFでレコードを区切り、NUL以降を文字列の値から除き、末尾ASCII空白を除去してから256バイトまで格納する。
- 先頭空白は保持。空レコードはLEN=0でBUF保持、EOFはLEN=FFFFでBUF保持。
- Ctrl+ZはWindowsテキスト入力のEOFとして扱う。
- 長い行は全体を消費するが、格納候補は最大256バイトだけ保持する。末尾空白除去を先に行う意味を維持するため、256バイト目の空白の後に非空白があれば、その空白を削らない。
- キーボードINの128バイト制限とは分離する。

## 出力

- 各メモリ語の下位8bitを取り、画面OUTの00/E0〜FFフィルタを通さない。
- レコード末尾にLFを付加したCStringをfputsへ渡す原経路に合わせ、最初のNULで途中終端する。NULの後にある付加改行も出力しない。
- すべてのLFをCRLFへ変換する。元々CRLFであればCRCRLFとなる。
- 最初のOUTでCreate＋truncateし、以後のOUTは開いたストリームへ追加。LEN=0ならOpenしない。LEN>0で先頭バイトがNULの場合はOpen／切詰めだけが起きる。
- Windowsでは出力ファイルの共有モードを0にして、開いている間の外部読取・書込を拒否する。
- 正常終了、異常終了、リロード、戻り、装置設定の適用、文書切替、アセンブル、通常のウィンドウ終了でCloseする。Close時の書込失敗を握りつぶさず表示する。

短い出力はバッファに保持され、RETのClose後にファイルで読める。戻るとClose→先頭から再実行→OUTで再Openとなる。最初のOUTより前へ戻す場合は新しいOUTがなく、直前にCloseした内容がディスクへ残る。

## 検証

Rustのファイル装置テスト10本を追加し、全体は25本。既存のCPU・アセンブラ・パイプライン試験も通過している。

| 原版の固定データ・追加試験 | 確認内容 |
|---|---|
| `followup_file_input.json` 9件 | TrimRight、256バイト制限、EOF・空文字、BUF保持 |
| `native_20261027.json` 入力5件 | 実ディスクからの最初のIN。NUL・Ctrl+Z・末尾空白 |
| `native_io_20261027.json` 11時点 | 初回切詰め、サイズ0・共有拒否、RET後の8バイト、戻り後の内容、NUL出力の1バイト |
| 日本語256バイト | CP932の入力→出力を命令・フェーズ・最小STEPで実行 |
| 空OUT・先頭NUL・生バイト・改行 | Openの有無、E0/FFの保持、各LFのCRLF化 |
| ストリーム | 空行・EOFの区別、長い行、trimとcutの順序、連続IN |
| エラー・Close | 欠損パスの安全停止、明示Close・異常終了での確定 |
| 同一ファイル | 同じパスとハードリンクを、書込前に拒否 |

一時ファイルで実際のWindows共有ロックとディスク内容を検証した。管理サンドボックスがハードリンク作成を拒否する環境では、その試験を通常のWindows実行環境で確認する必要がある。今回の25テストは同一ファイル・ハードリンク検査を含めて通過した。

WindowsのTauri実画面でも、「ファイル入出力」サンプルと新しい入出力設定を使って確認した。入力はCP932の「あｱ＋末尾空白2個」と「ABC」の2レコード。EOFまで47命令で正常終了し、実ファイルは `82 A0 B1 0D 0A 41 42 43 0D 0A` の10バイトで一致した。出力先の保存ダイアログでパスを確定し、設定を適用した段階では、まだ出力ファイルが存在しないことも確認した。

そこからBackspaceすると46命令の位置まで再実行され、出力先はサイズ0・外部読取拒否・バッファ10バイトとなった。RET前のこの状態からウィンドウを閉じると、Closeを待って全10バイトが保存され、共有ロックも解除された。入力・出力バイトと確認結果は `analysis/results/implementation-file-devices/gui-verification.json` に保存した。

## 安全側への変更と未照合範囲

- 入力と出力が同じファイル（ハードリンクを含む）、または出力が編集中のCASLソースと同じ場合は拒否する。原版の誤操作・クラッシュの再現は行わない。
- パスは適用時に絶対パスにする。以後に別フォルダの文書を開いても、選択済み装置の基準ディレクトリを変えない。
- 途中の装置変更は移植版では明示的な「適用してリロード」に統一した。原版の全切替経路との一致を主張しない。
- 出力バッファは4096バイト。採取した短い出力の時点・内容は一致するが、原版の長い出力のflush境界までは照合していない。
- 原版でNUL／Ctrl+Zの後に行う2回目以降のINは未照合。移植版はNUL後も物理行末まで消費し、Ctrl+Z以降はCloseまでEOFにする方針。
- ASCII以外の特殊な末尾空白の扱い、入力ファイルの共有フラグ、ストレージ障害時の全挙動は未照合。
- OSによる強制終了やプロセスクラッシュ時のバッファ保持は保証しない。通常の終了経路では終了前にCloseを待つ。
- cmk・設定の永続化は後続実装で対応済み。指定アドレスまでの実行は未実装。
