# メニューバーと複数タブのワークスペース

更新: 2026-10-30。

## 操作

上部はWindowsのネイティブメニュー「ファイル(F)」「編集(E)」「表示(V)」「実行(R)」「プロジェクト(P)」「ヘルプ(H)」。ファイルの開く・保存・名前を付けて保存、Undo/Redo、クリップボード、検索などをここに集約した。左側はエクスプローラー、中央はソースとシミュレーターを配置できるタブグループ。境界をドラッグして幅を変更できる。

1. 「ファイル → ファイルを開く」でcasを開く。複数選択に対応し、既存のタブに追加する。同じパスを開いた場合は既存タブへ移動し、未保存の編集を保持する。
2. ソース右上の分割プレビューアイコン、またはF5でアセンブルする。成功すると、そのファイル専用のシミュレーターを右に開く。同じファイルを再ビルドすると既存のシミュレータータブを更新する。
3. ソースとシミュレーターは別々にタブを選択できる。左で別のソースを参照しながら右で実行可能。右上のファイルアイコンで対応するソースへ戻る。配置表の行をクリックすると該当ファイル・行を選択する。
4. 実行はF6、1STEPはF10、停止はShift+F5またはCtrl+Q。シミュレーターにフォーカスがあり入力欄を編集していないときはEnterで1STEP、Backspaceで戻る。

| キー | 操作 |
|---|---|
| Ctrl+N / Ctrl+O | 新規 / 開く |
| Ctrl+S / Ctrl+Shift+S | 保存 / 名前を付けて保存 |
| Ctrl+W | フォーカス中のグループのタブを閉じる |
| Ctrl+Tab / Ctrl+Shift+Tab | フォーカス中のグループ内で次 / 前のタブ |
| Ctrl+1 / Ctrl+2 | 第1 / 第2グループへ移動 |
| Ctrl+B / Ctrl+J | エクスプローラー / アセンブラ出力の表示切替 |
| Ctrl+F | ソース内検索 |
| Ctrl+, | 設定 |
| Ctrl+Shift+Enter | 対応するシミュレーターを右に開く |

ソースタブの●は未保存、シミュレーターの緑の点は実行中、黄色の点は入力待ちまたは再アセンブルが必要な状態。タブの×または中央クリックで閉じる。ソースを閉じる際は未保存の変更を確認し、対応するシミュレーターも閉じる。シミュレーターだけを閉じた場合はソースを残す。

## カラーテーマ

「ファイル → 設定 → カラーテーマ」で「ライト」「ダーク」「OSと同期」を選択し「保存」で反映する。旧設定で項目がない場合は従来のダークを使う。選択は次回起動時にも復元する。「OSと同期」は起動中のOSのライト／ダーク変更にも追従し、固定テーマではOS変更の影響を受けない。

ソース、シンタックスハイライト、タブ、サイドバー、CASLのレジスタ・ラベル・スタック、COMET図、ダイアログ、Windowsのタイトルバー・ネイティブメニューを切り替える。CPU・メモリ・編集中の内容は維持する。

Windows実画面でライトの各表示、現在のOSダーク設定との同期、ライト選択の再起動後の復元を確認した。起動中のOS変更通知と固定テーマの分離は自動テストで検証し、普段のOS設定は変更していない。記録: `analysis/results/themes/gui-verification.json`。

## 最近使用したファイル・自動保存

「ファイル → 最近使用したファイル」に、開いた／保存したCASファイルを新しい順で最大20件表示する。cmkを開いた際の登録CASも含む。Windowsのパス表記・大文字小文字の違いを重複登録しない。選択でファイルを開き、既に開いている場合は未保存の編集を保持してそのタブへ移動する。読めないファイルはエラーを通知し、現在の編集内容は保持する。「履歴を消去」で一覧を空にできる。履歴は設定に保存する。

「ファイル → 自動保存」はチェック付きのオン／オフ項目。既定はオフ。オンの場合、保存先のあるCASファイルを最後の編集から1秒後にCP932／CRLFで保存する。新規ファイルは最初に通常の保存で保存先を指定する。日本語入力の変換中、別のファイル操作中、ダイアログ表示中は待機する。オフにすると待機中の保存を取り消す。保存失敗時は未保存の印を残してエラーを表示し、次の編集または手動保存で再試行する。cmkの登録変更は通常のcmk保存を使う。オン／オフは次回起動時にも復元する。

専用プロファイルを使ったWindows実画面で、履歴からの読込、自動保存チェック、編集後の実ファイルへのCRLF保存、未保存表示の解除、再起動後の履歴とチェックの復元を確認した。記録: `analysis/results/file-menu/gui-verification.json`。

## 独立して保持する状態

ファイルごとに本文、保存済み本文、キャレット、選択、スクロール、ブラウザー標準のUndo/Redo履歴、診断を保持する。シミュレーターごとにCPU・メモリ、実行位置、出力、入力待ちと入力途中の文字、戻り、実行速度、STEP粒度、CASL/COMET、GRの16進・10進同時表示／2進のみ、メモリ表示番地、入出力装置を保持する。

編集中のファイルがビルド入力に含まれるシミュレーターだけを停止し、再アセンブルまで操作を無効にする。独立したファイルの実行は継続する。ビルド失敗やリロード・戻り・閉じる操作も対象のセッションにだけ適用する。名前を付けて保存してもソースとシミュレーターの対応は維持する。

入出力装置の変更は対象タブをリロードし、次回作成するシミュレーターの既定値にも保存する。別タブが同じファイルを出力先や競合する入力先として利用している場合は拒否する。予約はそのシミュレーターを閉じるまで有効。閉じる際はファイル出力の確定を先に行い、失敗時にはタブを残す。

## cmk

「プロジェクト」メニューでcmkの作成・開く・保存・メイン指定・追加・除外を行う。現在のcmkは1つ、登録は20ファイルまで。通常のファイルタブはこの上限とは独立して複数開ける。cmkを開いても既存の編集タブと独立したシミュレーターを残す。

登録ソースの右上ボタンは、そのソースを先頭にして他の登録ファイルとリンクする。「メインをアセンブルして右に開く」は★の登録ファイルを対象とする。副プログラムだけでは単独実行できない場合、メインのプレビューを使う。登録ファイルの編集は、それをリンクしたシミュレーターを再アセンブル待ちにする。

## 構成と検証

- `src/workbench.ts`: ファイルと1対1のシミュレーター、パスの重複排除、ビルド依存関係。
- `src/editor.ts`: ファイルごとにtextareaを保持し、タブ切替でUndo履歴を失わない編集面。
- `src/simulator.ts` / `src/layout.ts` / `src/style.css`: 実行画面、左右タブグループ、エクスプローラー、ダーク配色。
- `src-tauri/src/workspace.rs`: IDごとのRustセッション、装置の競合・保存先保護、出力確定。
- `src-tauri/src/app_menu.rs`: Windowsネイティブメニューとアクセラレーター。

`npm run test:editor` は色分け6本とタブモデル6本の計12本。`cargo test --workspace --locked --offline` はコア39本とデスクトップ4本の計43本。セッションのCPU・ビルド失敗・入力待ち・戻り・装置変更・設定保存失敗が別セッションへ波及しないことを検証する。

Windows実画面では2つのcasを同時に開き、右上のボタンから2つのシミュレーターを作成。ALPHA / BETAをそれぞれ9命令で正常終了し、GR1=1 / 9と異なる出力が切替後も保持された。片方だけの編集による再アセンブル待ち、別ソースへの切替後の編集メニューUndoも確認した。更新したEXEでもCtrl+O、F5、F10（1命令だけ進行）、F6を確認。Ctrl+Shift+Sで保存したコピーは元の140バイトと一致し、Ctrl+Sはダイアログを出さず上書き保存した。名前変更後も1対1の対応を保持し、シミュレーターだけをCtrl+Wで閉じても編集タブは残った。

cmkを開くと既存タブを残してmain.cas・sub.casが追加され、F5で6語をリンク、F6で4命令実行してGR1=7・正常終了した。配置表のsub.cas:3をクリックすると、sub.casの該当行が左で選択された。左右の幅変更でも実行結果を保持した。追加の確認記録は `analysis/results/workbench-ui/gui-verification.json`。

検証時は `XCASL2_CONFIG_DIR` に検証専用フォルダーを指定できる。未指定なら従来どおりアプリの設定フォルダーを使用する。

CASLモードでは[ラベル・スタック表示](CASL_INSPECTION.md)も利用できる。SP追従・表示番地はタブごとに保持する。レジスタとラベルの10進値の符号表示は設定で共通に切り替える。

COMETモードは[左上のCPUブロック図・左下の出力・右側のメモリとソース](COMET_LAYOUT.md)を表示する。図の実値と転送経路の強調はSTEPに追従する。メモリはPR追従と番地の手動指定に対応する。

## 残る制限

開いているタブ・未保存本文・実行状態の再起動後の復元は未実装。設定の永続化は引き続き有効。複数cmkを同時に管理する機能は未実装。ソース同士の左右表示とタブの並べ替え・グループ移動は[分割とドラッグ操作](SPLIT_TABS.md)を参照。
## シミュレーターを開く位置

ソース右上のアセンブルボタンは通常、シミュレーターを横に表示します（F5）。Altを押している間はアイコンと説明が切り替わり、Alt＋クリック、またはAlt＋F5でソースと同じタブグループに開いて選択します。実行メニューからも選べます。

同じソースのシミュレーターが別グループに存在する場合、Alt操作ではそのタブをソースのグループへ移動します。1ソースにつき1シミュレーターの対応を維持します。通常のF5では既存シミュレーターの位置を再利用し、Shift＋F5は停止です。アセンブルが失敗した場合はシミュレーターのタブを新設・移動しません。

ステータスバーは現在のテーマのサーフェス色と文字色を使い、ライト／ダーク／OS同期に追従します。エラーはテーマに応じたエラー色で表示します。

## ツールチップ

アプリのボタン・タブ・ステータス・シミュレーターの説明は、WebView2標準の`title`表示から独自のDOMツールチップへ変更しました。Altを押している間も表示し、ボタンの説明が変わると表示中の文字列も更新します。通常は450msのホバー、またはキーボードフォーカスで表示し、Escape・クリック・スクロール・ウィンドウの非アクティブ化で閉じます。

表示はテーマに追従し、改行・画面端での位置調整に対応します。Popoverのトップレイヤーを使い、パネルやダイアログの後ろに隠れないようにしています。ARIAのtooltip／describedbyを使い、文字列はテキストとして表示します。Monaco本体のホバーや検索ボタンの説明は引き続きMonacoが管理します。COMET SVGの説明はネイティブの視覚ツールチップと重ならないよう`desc`で保持しています。

検証：エディター関連54テストが成功。ブラウザーでAlt中も説明が残ること、Escapeで閉じること、アセンブルボタンの説明属性の切り替えを確認。デスクトップ版でアセンブルボタンの独自ツールチップが表示されることも確認しました。記録は`analysis/results/tooltips/`。
