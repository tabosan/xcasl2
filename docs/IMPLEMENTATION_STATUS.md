# Rust + Tauri 実装状況

更新: 2026-10-29。対象バージョン: xCASL2 0.1.0。

## 起動とビルド

WindowsではRustのMSVCツールチェーン、Visual Studio C++ Build Tools / Windows SDK、Node.js、Microsoft Edge WebView2が必要。この端末ではコンパイラ・依存ライブラリを使って検証している。

```powershell
npm ci
npm run tauri dev
```

初回のRust依存取得・コンパイルには時間がかかる。開発中はViteをTauri CLIが起動する。`npm run dev`だけでは画面のプレビューになり、Rustの実行機能は利用できない。

```powershell
cargo test -p wcasl2-core --locked
npm run build
npm run tauri -- build --debug --no-bundle
```

最後のコマンドはフロントエンドを埋め込んだ `target/debug/xcasl2-desktop.exe` を生成する。Viteサーバーなしで起動できる。リリース最適化する場合は `--debug` を外す。インストーラ生成は現時点では無効。

## 操作できる範囲

- ソース同士の左右表示、タブのドラッグ並べ替え・グループ間移動・端ドロップでの分割、グループの統合。ソースとシミュレーターを共通のグループに配置できる。[操作と実装](SPLIT_TABS.md)を参照。

- CASLソースの編集、CP932で開く、CP932 / CRLFで名前を付けて保存。
- ファイル(F)・編集(E)等のネイティブメニュー、複数casの編集タブ、各cas専用のシミュレータータブ。右上のプレビュー操作でアセンブル後に右グループへ表示。[操作と検証](WORKBENCH_UI.md)を参照。
- 命令・疑似命令・マクロ・レジスタ・ラベル・数値・文字列・コメントのシンタックスハイライト。入力、ファイル切替、縦横スクロールに追従。[実装と検証](EDITOR_HIGHLIGHT.md)を参照。
- サンプル4件（Hello、入力を出力、1〜10の合計、EOFまでファイル入出力）。
- アセンブル・リンク・ロード。配置番地・初期化値を設定可能（既定は0020・FFFF）。
- cmkの読込・保存、20ファイルまでの追加・除外、編集ファイル切替、メイン指定、ファイル名・行番号付きのエラー／配置表。
- 配置・初期化・時間間隔、STEP粒度、表示、メモリ表示先頭、入出力装置の設定を保存し、起動時に復元。[cmkと設定の実装](WCASL2_PROJECT_SETTINGS_IMPLEMENTATION.md)を参照。
- 「ファイル」に最近使用したCAS（最大20件・履歴消去）と自動保存（保存先のあるCASを編集後1秒で保存）を追加。履歴とオン／オフは次回起動にも復元する。
- 設定のカラーテーマでライト・ダーク・OSと同期を選択し、画面全体とWindowsのメニューへ反映。OSと同期は起動中の変更にも追従する。選択は保存し、既定は従来のダーク。
- 命令・フェーズ・最小STEPの切替、時間実行、高速実行、停止、リロード。IN/OUTは原版と同じ12語に展開する。
- CASL / COMET表示の切替。COMETは左上にIR・Decoder・Controller・PR・SP・縦並びGR・MAR・Adder・EA・MDR・ALU・FRのブロック図、左下に出力、右に語ごとのメモリと対応ソースを表示。実レジスタ値と直前の転送経路を強調し、PR追従／番地固定に対応。[COMETの配置](COMET_LAYOUT.md)を参照。
- GR0〜7、PR、SP、OSZ、IR、CALL深さ、配置番地と機械語、64語ずつのメモリ表示。GRは16進・10進を同時表示し、「2進のみ」チェックで切り替える。PR・SPは常に16進のみ。10進値は既定で2の補数による符号付きで、設定から符号なしへ変更できる。
- CASLモードのラベル一覧（ラベル・番地・16進・10進、DC/DS/リテラルの全語）とスタックエリア（番地・16進、SP追従／固定番地）。ラベル欄の符号切替チェックは撤去し、レジスタと共通の符号付き／符号なし設定に統合。[操作と原版の確認](CASL_INSPECTION.md)を参照。
- キーボードIN、空入力、EOF。CP932バイトをゼロ拡張し、DC文字列の符号拡張と区別。
- ディスプレイOUT。下位8ビット、00/E0〜FFの置換、自動改行なし、44バイト折返し、12行保持。
- ファイルIN / OUT。装置選択、先頭からの読直し、末尾空白除去後256バイト、NUL・Ctrl+Z、初回OUTでの切詰め、CRLF、短い出力のClose時確定、再実行時のファイル作成規則に対応。[実装・検証記録](WCASL2_FILE_DEVICES_IMPLEMENTATION.md)を参照。
- 戻りは初期状態から再実行し、再通過するINで入力を求め直す。選択中の粒度で「STEP回数−1」回を再実行する。途中で粒度を変更した場合も原版のカウンタ方式に合わせ、以前の粒度の履歴は復元しない。
- F5でアセンブル、F6で実行、F10で1STEP。シミュレーターの入力欄以外にフォーカスがあるときはEnterで1STEP、Backspaceで戻る。Shift+F5・Ctrl+Qで時間実行停止。
- 編集後は依存するシミュレーターを再アセンブルするまで古い実行イメージの操作を無効化。アセンブル失敗でも対象の旧セッションを破棄し、ほかのタブは保持する。

`npm run test:editor` は色分け6本・タブ管理6本・レジスタ・ラベルとスタック6本・グループ配置7本・補助編集履歴3本・履歴と自動保存3本・テーマ切替2本・COMET表示3本の計36本が通過。Windows実画面でも入力・Undo・ソース行選択と、100行の末尾・長い行の右端での表示を確認した。ワークスペース化後も2つのプログラムを独立実行し、出力・レジスタの保持とタブ切替後のUndoを確認した。

1420件はCPUの**実行段階**の照合。フェーズと最小STEPの途中状態は別途341トレースで照合している。データパス図は実際のコア状態に基づく新UIであり、旧画面の全点灯ビット・色・配置の完全再現ではない。ビルド失敗時のエラー件数・文章・部分機械語は完全一致の対象にしていない。

追加セッション試験で、取出途中まで戻る操作、粒度変更後の戻り、MDRに保持した値のコミット、STの書込タイミング、最小STEPでのINと再入力を検証した。追加の観測と実装規則は[パイプラインの実装・照合](WCASL2_PIPELINE_IMPLEMENTATION.md)を参照。

Windows上のTauri実画面でも、Helloのアセンブル→10命令実行→GR1=3・出力・正常終了、ファイルダイアログからのecho.cas読込、日本語「あｱ」の入力→GR0=3バイト・同じ文字列の出力→18命令で正常終了を確認した。保存ダイアログによる `analysis/results/implementation-smoke.cas` の内容とCRLFをバイト比較した。これらは原WCASL2の画面ではなく、今回実装したTauriアプリの動作確認。

cmkの画面確認では相対パスの2ファイルをリンクして4命令で終了し、メイン変更・cmk保存・再読込後は2命令で終了した。設定の配置0040・2345ms・COMET表示は再起動後に復元され、実際の配置にも反映した。現在はデスクトップ側にセッション分離と設定保存失敗時の状態保持を検証する4テストがあり、コアと合わせたRustテストは45本。

ファイル装置の画面確認では、日本語を含む2レコードをEOFまで47命令で処理し、CP932＋CRLFの10バイトが一致した。戻り後の再Open・サイズ0・共有拒否、ウィンドウ終了時の10バイト確定も確認した。

K61_advance.casの9命令目の異常終了は、NOPの未使用ビットに対する過剰なレジスタ検査が原因だった。修正版は3379命令で正常終了し、元EXEの最終CPU・全3000語・出力と一致する。[調査と修正](K61_ADVANCE_COMPATIBILITY_FIX.md)を参照。

## 未実装・意図的な差分

- COMET図の全制御信号・旧版の点灯状態との完全一致。ブロックの配置と全レジスタ枠は再現し、色は選択中のテーマを使う。
- NUL／Ctrl+Z以降の連続INと、長い出力のflush境界の原版照合。入出力装置の途中変更は適用時リロードへ統一。
- 指定アドレスまでの実行、初期化しないモード、GR値設定、印刷。
- 開いているタブ・未保存本文・実行状態の再起動後の復元、複数cmkの同時管理。
- `literal_address`（`=MAIN`等）は原版の特殊な割当規則を保留し、未対応エラーとする。
- `duplicate_global` は原版の「重複診断後も成功扱い」を再現せず、重複公開名のエラーで止める。
- キーボード入力上限は初版では**CP932で128バイト**。原版の日本語DDV境界と同一と断定しない。
- encoding_rsのSHIFT_JIS（Windows-31J）を利用。原版とフォント・未完のマルチバイト列・制御文字の見え方は異なる。CP932の全拡張文字の往復を網羅した保証はない。
- レジスタを使用する命令の不正r/xニブルは安全に異常終了する。NOPの未使用r/xは許容し、0000〜00FFをNOPとして実行する。原版のメモリ破壊・クラッシュは再現しない。
- DS領域は指定の初期化値を保持する。START/END・ラベル検査・空行・小文字・行長200バイト・リテラル表記共有・長いシフト量は、採取済みケースを互換基準とする。ラベル配列等の正確な限界規約は引き続き解析対象。

元の `Wcasl2.exe` と解析データは変更しない。互換仕様書は原版の観測結果、本文書は移植版の実装状況として分けて扱う。
