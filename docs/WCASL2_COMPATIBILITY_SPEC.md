# WCASL2 実行ファイル互換仕様書

## 1. 対象と読み方

本書はRust版を実装するための、対象バイナリに基づく仕様である。一般的なCASL II処理系の仕様を、そのままWCASL2の仕様として扱わない。特に構文検査、文字コード、初期化、画面出力、ステップ粒度、異常系に固有の挙動がある。

| 項目 | 値 |
|---|---|
| ファイル | Wcasl2.exe |
| サイズ | 425,984 bytes |
| SHA-256 | `389365c3f036b9c5461d669dafe98d7772b412167d3aee1730fb441e8275f74e` |
| Windowsファイル版情報 | 1.0.7.0 / 1, 0, 7, 0 |
| バージョン情報ダイアログの内容 | WCASL-II Version 1.08 |
| ダイアログ内の著作者表記 | Hiroyoshi Watanabe / Copyright 2001–2005 |
| PE形式 | x86 / PE32 / ImageBase `00400000` |
| 実装の特徴 | MFCのMDIアプリ、ANSI版Win32 API、C++クラス情報が残存 |

版情報が一致しないので、「1.07互換」「1.08互換」という名前だけで互換対象を特定してはならない。上記ハッシュを基準にする。

## 2. アプリ全体の構成

### 2.1 文書とウィンドウ

MFCのMDI方式で、複数の子ウィンドウを扱う。主な文書は次のとおり。【U/S】

| 文書・画面 | 主な役割 |
|---|---|
| CASL文書 | `.cas` のソース編集 |
| Make File文書 | `.cmk` のファイル構成・メイン指定 |
| Assembler Output | アセンブル・リンクのメッセージ一覧 |
| Casl Simulater | レジスタ、ソース行、ラベル、スタック、出力の表示 |
| COMET Simulater | データパス図、メモリ、サイクル、出力の表示 |

タイトル内の `Simulater` は原版の綴り。内部に `CAsmDoc`、`CCaslDoc`、`CMakeDoc`、`CSimDoc`、`CSimViewS`、`CSimViewD` などがある。

起動直後は文書のない灰色の作業領域。新規作成にはCASL文書とMake Fileの2種類があり、Ctrl+Nでは種類選択ダイアログが出る。【U】

### 2.2 主なコマンド

| 分類 | 機能 |
|---|---|
| ファイル | CASL新規・開く・保存・別名保存・閉じる、Make新規・開く、最近使用したファイル、終了 |
| 編集 | 元に戻す、切り取り、コピー、貼り付け |
| 印刷 | 印刷、プレビュー、プリンタ設定 |
| 表示 | ツールバー、ステータスバー、CASL表示で符号無10進への切り替え |
| プロジェクト | アセンブル、CASLシミュレート、COMETシミュレート、ロードモード |
| シミュレータ | リロード、STEP設定、STEP実行、1STEP戻る、時間実行、停止、時間設定、GR値設定、入出力装置設定 |
| ウィンドウ | 重ねて表示、並べて表示、アイコン整列、文書切り替え |

ソース文書、出力文書、CASL表示、COMET表示でメニュー内容が変わる。【U/S】

検索・置換の文字列はMFC共通リソースにあるが、対象のソース編集メニューに検索・置換項目はない。共通リソースの存在だけから公開機能とみなさない。

## 3. ソースファイルと構文

### 3.1 文字と行

ソースはANSIのバイト列として扱われる。今回のWindows環境ではCP932。Rust内部のUTF-8文字列を、そのまま旧アセンブラの文字列データとして解釈してはならない。【S/E/U】

| 項目 | 確認結果 |
|---|---|
| CRLF | 受理 |
| LF | 低レベルアセンブルで受理 |
| CRのみ | 行区切りとして機能せず、正常にアセンブルされないケースを確認 |
| 命令・GR名 | 大文字小文字を区別。`lad`、`gr1` はエラー |
| ラベルなし命令 | 行頭に空白またはタブが必要 |
| タブ区切り | ラベル・命令の区切りとして受理 |
| オペランド内空白 | 一般的な空白無視ではない。`LAD GR1, 1`、`LAD GR1 ,1` はエラー |
| 行末コメント | `;` で開始。ただし文字列内の扱いに不具合あり |
| コメントだけの行 | 受理 |
| 空行 | 本対象ではエラーになるケースあり。後述 |

`RET` を第1桁に書くとラベル欄として読まれ、命令コードエラーになる。` RET` は命令となる。

### 3.2 空行の互換挙動

`MAIN START` の前、またはプログラム途中に空行を入れると、命令コードエラーになるケースをEで確認した。実機でも、コメント行・空行・MAINからなる `ui_valid.cas` に対して、空行を含むプログラムがアセンブルエラーになることを確認した。【E/U】

エラーの行番号・空白表示は、前処理や出力一覧の表示で見た目が変わる。今回の実機は `1 行目: 命令コードのエラーです．` と表示した。空行を自由に許す新パーサは、この点では原版互換ではない。

追加54ケースではCRLF/LFで結果が一致した。START前、STARTとRETの間、RETとENDの間の空行・空白だけ・タブだけの行は命令コードエラー。これらの位置のコメント行は受理される。END後の空行・空白・タブ、末尾改行なし、改行1/2/3個は成功する。一方、END後のコメントだけの行は、ソース分割後に次のプログラムとして処理され「ENDがありません．」となる。全配置の無制限な網羅ではなく、試験した配置と入力は `followup_boundaries.json` を参照。【E】

### 3.3 ラベル

| 条件 | 確認結果 |
|---|---|
| 長さ | 8バイト以内。9文字のASCIIラベルはエラー |
| 先頭 | `A`–`Z` が必要 |
| GR0–GR7と同名 | ラベルとして使用不可 |
| 命令名と同名 | `LD DC 1` のような定義を受理 |
| 重複 | 同一プログラム内ではラベル重複エラー |
| ローカル範囲 | START–ENDの各プログラムの内部 |
| 外部公開名 | STARTのラベル |

**先頭以外の文字検査に実装上の不具合がある。** 元コードは、後続文字を検査する際に先頭文字を入れたレジスタを再参照する。結果として、`A_B`、`A@B`、`A[B`、`A\B`、`A^B`、``A`B`` を受理した。【E/S: `00405B78`–`00405BB5`】

したがって、原版互換モードを `[A-Z][A-Z0-9]{0,7}` の正規表現だけで実装すると互換性を失う。一方、先頭 `_` の `_ABC` はエラー。

`A+1` をアドレスオペランドに書くと、算術式として評価せず、名前が `A+1` の外部ラベルとして扱い、未定義ならリンクエラーになる。【E】

### 3.4 レジスタ指定

汎用レジスタは `GR0`–`GR7`。指標レジスタは `GR1`–`GR7`。【E/S】

| 例 | 結果 |
|---|---|
| `LAD GR1,1,GR7` | 成功 |
| `LAD GR1,1,GR0` | XRレジスタエラー |
| `LAD 1,1` | GRレジスタエラー |
| `LAD GR8,1` | GRレジスタエラー |
| `LAD GR1,1,2` | XRレジスタエラー |
| `LD GR1,GR2,GR3` | 2レジスタ型で指標レジスタは使用不可 |
| `JUMP 1,GR2,GR3` | オペランドエラー |

## 4. 疑似命令とマクロ

### 4.1 START / END

`名前 START [開始ラベル]`、` END` が基本形。STARTのラベルが外部公開名となる。開始ラベルを省略すると先頭から実行。最初のプログラムの指定開始ラベルはリンク段階で解決し、未定義ならリンクを中止する。【E/S】

追加確認（2026-10-27）: CALLの公開名参照は、そのプログラムを配置した先頭番地へ解決し、副プログラムのSTARTオペランドが示すラベルへ自動転送しない。先頭にDCがあれば、そのデータを実行する場合がある。副プログラムだけの未定義STARTオペランドは今回の確認例ではリンクエラーにならない。START仮説7ケースとK61_advance.casの配置メモリで確認した。[調査記録](K61_ADVANCE_COMPATIBILITY_FIX.md)を参照。【E】

本対象は、STARTを欠く小さなプログラムをアセンブル・リンクできるケースもある。標準文法を厳格化した場合との差分として扱う。`START` にラベルがない場合はラベルエラーとなる。【E】

END欠落、ENDのオペランドありはエラー。同一ファイル内に複数のSTART–ENDプログラムを書ける。低レベルの1セクション用ルーチンに複数プログラムを一括投入した場合のENDエラーを、アプリ全体の非対応と取り違えない。全体ビルドルーチンによる分割・リンクまで確認済み。【E/S】

### 4.2 DS

`[ラベル] DS 非負の10進整数`。DS 0も受理し、その位置にラベルを定義できる。`DS -1`、`DS #0002` はオペランドエラー。【E】

ロード後のDS領域の値は、ロードモードに影響される。DSを常にゼロで埋める実装にはしない。ロードモードがFFFF初期化なら、DSの未定義領域もFFFFのままになる。【E/S】

### 4.3 DC

10進整数、16進整数、文字列、アドレス定数、およびカンマ区切りの混在リストを扱う。【E】

| 入力 | 対象の結果 |
|---|---|
| `DC 32767` | `7FFF` |
| `DC 32768` | `8000` |
| `DC 65535` | `FFFF` |
| `DC 65536` | `0000` |
| `DC -32768` | `8000` |
| `DC -32769` | `8000`。単純な下位16ビット化なら7FFFになるため注意 |
| `DC +1` | `0001` |
| `DC #ABCD` | 受理 |
| `DC #abcd` / `#1` / `#12345` | エラー |
| `DC 'AB'` | `0041 0042` |
| `DC ''` | 0語。エラーにならない |
| `DC 'A''B'` | `0041 0027 0042` |
| `DC 'A B'` | 空白も1語として格納 |
| `DC 'A,B'` | カンマを文字として格納 |
| `DC 'A;B'` | 本対象はオペランドエラー。前処理でセミコロン以降が切れる |
| `DC 12X` | エラー |

負の10進値は少なくとも確認範囲では下限-32768へ丸める。32ビット整数範囲外のatoi相当の挙動まで、Rustの数値変換と同一とは確認していない。

文字列処理は1バイト→1語だが、DCでは符号付きcharを符号拡張する経路がある。例としてCP932の `DC 'あｱ'` はバイト `82 A0 B1` から **`FF82 FFA0 FFB1`** を生成する。【E/S】

これはINのゼロ拡張とは異なる。「文字は常に上位8ビット0」とまとめて共通実装しない。

### 4.4 リテラル

`=1`、`=-1`、`=#0001`、`='AB'` を扱い、END側のリテラル領域へ展開する。【E】

同じ表記のリテラルは共有する一方、数値として等しい別表記は別エントリとなる。確認例:

```casl
MAIN START
     LD GR1,=1
     LD GR2,=1
     LD GR3,=#0001
     RET
     END
```

再配置前の機械語は `1010 0007 1020 0007 1030 0008 8100 0001 0001`。`=1` は同一番地、`=#0001` は別番地となる。

`=MAIN` は数値・文字列リテラルと同じようには展開されない。受理されるケースは採取したが、表記ごとの解決結果は回帰データを優先し、汎用的な「アドレスリテラル対応」と断言しない。

### 4.5 IN / OUT の展開

それぞれ **12語**。`IN BUF,LEN` / `OUT BUF,LEN` の引数はラベル。`OUT 1,2` はオペランドエラー。【E/S】

```casl
     PUSH 0,GR1     ; 7001 0000
     PUSH 0,GR2     ; 7002 0000
     LAD  GR1,BUF   ; 1210 BUF
     LAD  GR2,LEN   ; 1220 LEN
     SVC  1        ; IN: F000 0001 / OUT: F000 0002
     POP  GR2      ; 7120
     POP  GR1      ; 7110
```

CASL表示では元のマクロを1行として示す。COMET表示では展開された各機械語がメモリ上に並ぶ。【U/E】

**CASLモードでも、命令ごとのEnterは展開後の機械語1命令ずつ進む。** 実機のOUT行先頭0024でEnterを1回押すと、PR=0026、SP=00B8、IR=7001 0000となった。出力サービス全体ではなく、最初の `PUSH 0,GR1` だけが実行された。Program上はOUT行が赤いまま。画面の1行とCPUの1命令を同一視しない。【U/E】

### 4.6 RPUSH / RPOP

RPUSHはGR1→GR7の順で `PUSH 0,GRn` を生成し14語。RPOPはGR7→GR1の順でPOPを生成し7語。GR0は保存しない。【E】

本対象は `RPUSH 1`、`RPOP 1` も受理し、余分なオペランドを無視する。一方 `RET 1`、`NOP 1` はエラー。【E】

## 5. アセンブル・リンク・ロード

### 5.1 処理段階

ソースをSTART–END単位に分割し、各プログラムを2パスで処理し、機械語・ローカルラベル・外部参照・表示用行情報を作る。その後、プログラムを順に配置し、再配置と外部参照の解決を行う。【E/S】

ローカルラベルを他プログラムから直接参照できない。`SUB START` のSUBは参照可能だが、SUB内の `HIDDEN DC 1` のHIDDENは、MAINから参照すると未解決になる。未定義ラベルは必ずしもアセンブルエラーではなく、外部参照としてリンクまで持ち越される。

### 5.2 初期化とアドレス

| 設定 | 対象の挙動 |
|---|---|
| 先頭アドレス | 設定可能。初期値のフォールバックは `0020` |
| 0で初期化 | メモリ・GRなどを0にする |
| -1で初期化 | メモリ・GRなどをFFFFにする |
| 初期化しない | ロード範囲外などの既存内容を保持する経路 |

今回の実機設定は `0020`、-1初期化だった。これはPEから読んだ設定のフォールバックとも一致する。【U/E/S】

初期化後、PRはリンク済みの開始番地、SPはリンク処理が決めたスタック側の値に設定される。FRはFFFF初期化時でも0。内部デコーダは0初期化、IRや作業レジスタにはFFFFとなるものがある。

通常の単一ソースの確認例では、ロードしたプログラムの末尾の次の位置をPとすると、リンク処理の末尾管理値は `P + 128`、シミュレータ開始時SPはその値+1となった。128語に関する内部処理と合成された `STACK / SECT` 表示が存在する。**例外経路を含むスタック領域の全規約は未確定。**【E/S】

初期SPを `FFFF`、`0000`、固定 `FF00` などと決め打ちしない。CPUコンストラクタ内のFF00は、実際のロード後SPとは異なる。

### 5.3 物理メモリ

対象のメモリ操作ルーチンは **3000語**、有効範囲 `0000`–`0BB7`。【S/E】

| 操作 | 範囲外の処理 |
|---|---|
| 1語読む | FFFFを返す |
| 1語書く | 書き込みを無視 |
| 2語書く | 先頭が0〜2998のときに限って2語を書く |

アドレスやレジスタは16ビットだが、実装の物理メモリを65536語と仮定してはいけない。範囲外アクセスを即座に例外停止させる処理とも異なる。

### 5.4 上限

| 項目 | 根拠と状態 |
|---|---|
| メイク登録ファイル | 最大20。専用エラーダイアログあり【S】 |
| ラベル配列 | 200要素を用いる。超過検査あり。START・リテラル等を含む正確な利用可能数の境界は要追加確認【S】 |
| 物理メモリ | 3000語【S/E】 |
| ソース行情報の配列 | 2000要素相当の固定配列【S】 |
| 1行の文字数 | 改行を除き200バイトまで。ASCIIコメント行200は成功、201/255/256は実機で「1行が長すぎます．」と診断し中止【U/E/S】 |

公開されている旧版履歴には「1行256文字、2000行」とあるが、**今回のEXEの200バイト検査と一致しない**。公開説明を優先してバイナリの検査を消さない。長い行の例外は実機ではアセンブル中止として回収される。201で失敗した後、編集バッファを200へ変更して再アセンブルできた。Unicorn単体のSEH未実装エラーを原アプリのクラッシュと解釈しない。【U/S】

### 5.5 診断

エラー一覧は、行番号、ラベル、命令、短縮したオペランド、エラー文を組み立てる。長いオペランドを `..` 等で短縮する経路がある。失敗時でも部分的な機械語や語数が作成されるので、「エラーなら内部メモリも空」と仮定しない。【E/S】

エラー分類は14件のテーブルを持つ。0は空。主要な番号は次のとおり。

| 番号 | 内容 |
|---|---|
| 1 | ラベル重複 |
| 2 | ラベル長過大 |
| 3 | ラベル文字不正 |
| 4 | ラベル欄エラー |
| 5 / 6 | GR / XRレジスタエラー |
| 7 | 命令コードエラー |
| 8 | オペランドエラー |
| 9 | オペランドのラベルが見つからない |
| 10 | STARTエラー |
| 11 | ソースプログラムなし |
| 12 | レジスタ名のラベル使用 |
| 13 | 2レジスタ型に指標レジスタを併記 |

さらに、空ソース、END欠落、メモリ・ラベル配列不足、未解決外部名、グローバル名重複など、独立したメッセージがある。

グローバル名を重複させたEのケースでは、重複エラーのメッセージと、その後の「ｴﾗｰはありません．」が両方出た。**診断文の存在と最終成功扱いが矛盾する経路がある。** このケースのUI全動作を互換の必須要件とするかは、移植前に実機で再確認する。

## 6. CPU命令

### 6.1 状態

GR0–GR7、SP、PR、FRは16ビット。IRは最大2語。COMET画面には、デコーダのopcode/r/x/adr、MAR、MDR、実効アドレス相当の作業値も表示する。【U/S/E】

FRの内部ビットは `OF=4`、`SF=2`、`ZF=1`。画面表記は **OSZ** 順。算術の符号判定は16ビット結果のビット15を使用する。

実効アドレスは16ビットの加算結果。指標指定なしでは第2語そのもの。指標ありでは第2語+対応GRの下位16ビットとなる。【S/E】

### 6.2 命令コード

各語の機械語表現は16ビット。第1語は上位8ビットopcode、次の4ビットr、下位4ビットxまたはr2。2語命令の第2語はadr。

| 命令 | メモリ・アドレス型 opcode / 語数 | 2レジスタ型 opcode / 語数 | 機能・FR |
|---|---|---|---|
| NOP | 00 / 1 | — | 状態維持 |
| LD | 10 / 2 | 14 / 1 | 値を格納、OF=0、SF/ZF更新 |
| ST | 11 / 2 | — | メモリへ格納、FR維持 |
| LAD | 12 / 2 | — | 実効アドレスを格納、FR維持 |
| ADDA | 20 / 2 | 24 / 1 | 符号付き加算、OF/SF/ZF |
| SUBA | 21 / 2 | 25 / 1 | 符号付き減算、OF/SF/ZF |
| ADDL | 22 / 2 | 26 / 1 | 符号なし加算、OF/SF/ZF |
| SUBL | 23 / 2 | 27 / 1 | 符号なし減算、OF/SF/ZF |
| AND | 30 / 2 | 34 / 1 | AND、OF=0、SF/ZF |
| OR | 31 / 2 | 35 / 1 | OR、OF=0、SF/ZF |
| XOR | 32 / 2 | 36 / 1 | XOR、OF=0、SF/ZF |
| CPA | 40 / 2 | 44 / 1 | 符号付き比較、OF=0、大小と一致をSF/ZFへ |
| CPL | 41 / 2 | 45 / 1 | 符号なし比較、OF=0、大小と一致をSF/ZFへ |
| SLA/SRA | 50 / 2、51 / 2 | — | 算術シフト |
| SLL/SRL | 52 / 2、53 / 2 | — | 論理シフト |
| JMI/JNZ/JZE | 61/62/63 / 各2 | — | SF=1 / ZF=0 / ZF=1で分岐 |
| JUMP/JPL/JOV | 64/65/66 / 各2 | — | 無条件 / SF=0かつZF=0 / OF=1 |
| PUSH | 70 / 2 | — | SPを減らし実効アドレスを格納 |
| POP | 71 / 1 | — | SPの内容をGRへ、SPを増加 |
| CALL | 80 / 2 | — | 戻りPRをスタックへ、分岐 |
| RET | 81 / 1 | — | 復帰、またはトップレベル終了 |
| SVC | F0 / 2 | — | 1=入力、2=出力 |

38種類の機械語形式に、IN/OUT/DC/DS/START/END/RPUSH/RPOPを合わせ、内部テーブルは46エントリ。90〜93はマクロ管理用の値であり、それをそのまま実行可能な独自機械語命令と解釈しない。

### 6.3 境界値の確認例

追加確認（2026-10-27）: opcode上位8ビットが00なら、下位のr/xビットを問わずNOPとして実行する。`DC 10`の値`#000A`もNOP。K61_advance.casではCALLが副プログラム先頭のこのデータへ入り、原版は正常に通過する。命令STEPの未使用EA計算と、命令／フェーズ／最小STEPの36トレースを追加採取した。詳細は[K61の調査](K61_ADVANCE_COMPATIBILITY_FIX.md)を参照。【E/S】

| 操作 | 結果 | FR(OSZの整数値) |
|---|---|---|
| ADDA: 7FFF + 0001 | 8000 | 6 |
| LD: 0000 | 0000 | 1 |
| LD: 8000 | 8000 | 2 |
| SLL: FFFF,16 | 0000 | 5 |
| SLL: FFFF,17 | 0000 | 1 |
| SLL: 0001,33 | 0002 | 0 |

上記を含む原コード実行の入力・全最終状態を `analysis/results/cpu_cases.json` に保存。1,420件を採取した。この件数は、Rust実装やCASL標準への適合試験が1,420件合格したという意味ではない。

### 6.4 シフト量の固有挙動

対象はx86の16ビットシフト命令を利用し、正のシフト量nについて、概ね「n−1のシフト→最後の1ビットシフト」の形でOFを取り出す。そのため、単純にnでシフトする数学的定義と、32以上で挙動が異なる。【S/E】

互換実装では、`n == 0` を別処理し、正の場合は `k = (n - 1) & 31` とした中間値を作り、最後に1ビット分を処理する。**`n & 31` だけでは32の挙動を再現できない。**

SLAでは符号ビットを保持し、有効な最上位ビットをOFへ移す。SRAでは符号拡張、SLL/SRLはゼロ埋め。n=0でもOFを0にしてSF/ZFを更新するケースを確認。

### 6.5 終了・不正命令・スタック

トップレベルRETの終了判定には、SPだけでなく **CALLの深さカウンタ** を使う。深さ0のRETはプログラム終了となり、SPから通常の戻り番地を読む処理とは別分岐になる。【E/S】

PUSH/POPだけでCALL深さは変化しない。CALLで増加、内部RETで減少。スタックの範囲外アクセスも基本的には物理メモリの範囲外規則の影響を受ける。ホストCPUのスタックやRustのVec境界とは切り離す。

未定義opcodeは「異常終了」の経路へ進む。未知のSVC番号は同じ不正opcode処理には入らず、確認したSVC 3ではレジスタやFRを変えずに実行フェーズを完了した。【E/S】

不正なr/xニブルや自己書換え後の不正命令の全組合せは未網羅。安全なRust実装でメモリ破壊を再現する必要はないが、原版と異なる停止を導入する場合は互換モードから分離する。

## 7. 入出力

### 7.1 入出力装置

入力はキーボードまたはファイル、出力はディスプレイまたはファイルを個別に指定する。設定ダイアログにはファイル名欄と変更ボタンがある。【S】

サービス呼び出し時のGR1はバッファ先頭、GR2は長さを保存してあるメモリのアドレス。長さそのものをGR2に入れる仕様ではない。

### 7.2 IN

| 条件 | 対象の挙動 |
|---|---|
| 普通の入力 | 1バイトを1語へゼロ拡張して格納 |
| 入力長 | バイト数をLENへ格納 |
| 空入力でOK | LEN=0000、バッファの残りは保持 |
| EOFボタン | LEN=FFFF、バッファを保持 |
| 半角カナB1 | 00B1。DCのFFB1とは異なる |
| CP932「あ」 | 0082 00A0の2語、LEN=2 |
| キーボード欄の制限 | DDX/DDVに128文字制限の指定【S】 |
| ファイル入力の切り詰め | 256バイトへ切り詰める分岐【S】 |

ファイル入力ではReadString後に末尾空白の除去を行い、その後256バイトへ制限する。先頭空白は残る。模擬ReadString→元の処理本体の9ケースでは、`' ABC  '`がLEN=4、`'A\t'`および`'A\r\n'`がLEN=1、空白だけはLEN=0になった。実ファイルの`AB  \r\n`でもBUF=0041 0042、LEN=2になった。キーボード入力にも同じtrimを掛ける仕様ではない。【U/E/S】

実ファイルの最初のINでは、`A\0B\r\n`はLEN=1でAだけを格納し、先頭NULはLEN=0・BUF保持となった。`A\x1AB`はLEN=1、先頭Ctrl+ZはEOF扱いでLEN=FFFF・BUF保持。このWindowsテキスト入力のCtrl+Zと、NULによる文字列途中終端を区別する。その後のINでのストリーム位置は未確認。【U】

キーボードの128とファイルの256を、共通の256文字上限に置き換えない。日本語の長さ制限がWindowsコントロール・DDVでどう数えられるかは、別途実機境界試験が必要。

IN本体はGR・FRを変更しない確認結果であり、マクロはGR1/GR2を保存・復元する。ただしバッファとスタックやLENが重なったときまで正常な使用例と同じ保証をしない。【E/S】

`analysis/results/io_cases.json` のIN試験は、入力ダイアログの結果だけを模擬し、その後の元のx86ルーチンによる書き込みを実行している。UIの最大文字数検査を通した試験ではない。

### 7.3 OUT: 画面

自動的なレコード末尾改行はない。連続したOUTは続けて表示される。【E/S】

| 項目 | 対象の挙動 |
|---|---|
| 文字抽出 | 各語の下位8ビット |
| フィルタ | 00、E0〜FFは空白20へ変換。01〜DFはそのまま内部表示バッファへ |
| 改行 | 0Aで次行へ |
| 1行の最大データ | 44バイトで折り返す |
| 表示保持 | 12行のバッファ。最下行から進むと上へ送る |
| 長さ0 | 何も表示せず、カーソルも進めない |

文字表示の描画はANSI文字列に依存するため、制御文字やCP932の不完全なバイト列の見た目を通常のUnicode文字描画と同一視しない。

### 7.4 OUT: ファイル

画面用の00/E0〜FFフィルタを通さず、下位8ビットを文字列へ追加し、末尾にLFを追加してテキスト出力する経路がある。【S】

ファイルは最初の出力時に `modeCreate | modeWrite | typeText` 相当のフラグで開く。実機では既存22バイトが最初のOUTでサイズ0になり、ABを2回出した後のRETで閉じると、実バイトは`41 42 0D 0A 41 42 0D 0A`になった。付加LFはディスク上でCRLFとなる。この短い出力はRET前までサイズ0・外部読取不可だった。長い出力のflush時点まで一般化しない。長さ0の場合はファイルを開く前に処理を抜ける分岐がある。出力先切替・エラー経路は追加試験が必要。【U/S】

元のCStdioFile::WriteString→fputs→strlen→模擬fwriteのプローブに加え、A・NUL・Bの3語、LEN=3を実機でもOUTした。RET後の実ファイルはAの1バイトだけで、後方のBと付加LFは保存されなかった。【U/E/S】

画面出力とファイル出力の改行・文字変換は別仕様として実装する。

## 8. 実行制御と表示

### 8.1 CASL画面

Registers、Labels、Stack Area、Program、Displayの領域を持つ。レジスタは16進、10進、2進で表示。FRはOSZ。Programはソース、アドレス、機械語を対応させる。Labelsにはリテラルも含まれ、DCの複数語が連続して表示される。【U】

観察した通常時の文字は主に緑、数値は青、実行箇所は赤、ビット列は紫系。正確な全色・フォント・ピクセル寸法は、DPIによる崩れと切り離して移植時に決める。【U/P】

「符号無10進」は表示だけの切り替えとして扱い、CPU内の16ビットデータ自体を変更しない。【S】

### 8.2 COMET画面

IR、Decoder、Controler、GR0–7、PR、SP、FR、MAR、MDR、Adder、ALU、Memory、Displayを図示する。綴り `Controler` も原版のもの。【U】

処理中のデータパスやレジスタ枠を赤に変え、サイクル名を表示する。最初の最小STEPでは `PR → MAR` の経路が強調され、PRはまだ0020、MARが0020となった。【U/E】

### 8.3 STEPの選択肢

| CASL表示 | COMET表示 | 内部値 |
|---|---|---|
| — | 最小の単位 | 0 |
| — | フェーズごと | 1 |
| 命令ごと | 命令ごと | 2 |
| 最後まで実行 | 最後まで実行 | 3 |
| 指定アドレス | 指定アドレス | 4 |

CASL表示では命令ごと、COMET表示では最小の単位を初期に確認。指定アドレスは16進で入力する。ダイアログには「命令の下位16ビットのアドレスを入力すると正常に動作しない」と注意書きがある。【U/S】

指定アドレスはPRとの比較で実行停止する単一の実行目標であり、複数の永続ブレークポイントの存在を確認したわけではない。アドレス到達時のフェーズ途中停止にも注意する。

### 8.4 フェーズと最小STEP

内部フェーズは次の4種類。【S/E】

1. 命令取出サイクル
2. 命令解読サイクル
3. アドレス生成サイクル
4. 命令実行サイクル

最小STEP・フェーズSTEPでは1語命令のアドレス生成を飛ばす。**命令STEPのループ `0040C480` は1語命令でもアドレス生成を通る**ため、実効アドレスの途中レジスタは粒度によって異なる。命令によって最小STEP数が異なる。最小STEPはホストCPUの命令1個や一定時間を意味しない。【E/S、追加294トレース】

取出は `MAR←PR`、アドレスバス選択、`MDR←Memory[MAR]`とPR加算、`IR←MDR`を1語ごとに行う。1語命令ではIR第2語を消さずに保持し、デコーダadrにも保持値が入る。`LAD GR1,7`、`LD GR1,GR2`（GR2=1234）の順では、最小／フェーズSTEPの実効アドレスは0007を保持する一方、命令STEPでは123Bになる。命令の結果のGR値とは分けて扱う。【E/S】

| 機械語の例 | 1命令完了までの最小STEP数 |
|---|---:|
| LAD GR1,1 | 13 |
| LD GR1,adr | 16 |
| LD GR1,GR2 | 8 |
| ADDA GR1,GR2 | 9 |
| SLL GR1,33 | 14 |
| PUSH adr,GR1 | 16 |
| POP GR1 | 10 |
| CALL adr | 17 |
| トップレベルRET | 7で終了 |
| 未定義FFFF | 11で異常終了 |
| SVC 3 | 23 |

上表は初期フェーズ0から元コードを実行した特定入力での結果。完全な各フェーズ・作業レジスタの遷移は `pipeline_cases.json` を参照。

追加の `pipeline_port_cases.json` は38機械語形式、分岐条件、スタック・メモリ境界、連続命令、入出力を98条件×3粒度で採取した。294トレース・1790遷移を保存。各転送と実装への対応は[パイプラインの実装・追加照合](WCASL2_PIPELINE_IMPLEMENTATION.md)に記載。

### 8.5 時間実行

選択したSTEP粒度でタイマー実行し、Ctrl+Qで停止する。内部で秒数×1000のタイマー周期を設定する。【S】

設定の保存キーは `intervaltime`。設定読込のフォールバックは2だが、今回の既存ユーザー環境ではダイアログに1が表示された。保存済み設定と出荷時フォールバックを区別する。コンボボックスの選択値は内部で+1されて秒数へ変換される。

「最後まで実行」には同期待ちループがあり、ループするプログラムでUI操作が応答する保証はない。移植版では実行を分割してキャンセル可能にする提案だが、それは使いやすさの改善である。【S/P】

### 8.6 1STEP戻る

Backspaceで、直前のSTEPの前へ戻る。実機では `LAD GR1,1` 実行後から、PR=0020・GR1=FFFFのロード直後へ復帰した。【U】

OUTマクロの最初のPUSHを実行したPR=0026・SP=00B8からのBackspaceでも、OUT開始前のPR=0024・SP=00B9へ復帰した。【U】

実装は単純な「命令の逆演算」ではなく、リセットして記録されたSTEP数まで再実行する方式を使う。【S: `0040D260`】

`0040D260` はSTEPカウンタ−1を目標に `0040C300` を再呼出しし、その際に現在の `+270`（STEP粒度）を参照する。過去の粒度選択を記録して再生する構造ではない。したがって粒度を変えてから戻る場合の「1STEP」は、過去の最後の操作をそのまま取り消す意味とは区別する。全GUI経路を跨いだ操作は引き続き追加確認対象。【S】

再実行がキーボードINを通過すると入力ダイアログを再要求する。実機ではAAを入力し、次のPOP GR2を終えたPR=002BからBackspaceすると、再入力BBBによってPR=002A・BUF=0042 0042 0042・LEN=3となった。さらにSVC直前まで戻すと、BUFとLENはロード時のFFFFに戻る。【U/E】

画面OUTは表示バッファを消して再出力するため、SVC前へ戻すと該当出力が消える。RPUSH/RPOPも展開後の各命令単位で戻る。ファイルOUTではClose後、再実行でOUTへ到達するとOpen(5001)・Writeを再発行する。【E/S】

実ディスクでも、ABを2回出してRETした状態からBackspaceすると、出力先が再びサイズ0・読取不可になった。1回のOUTまで順に戻し、さらに最初のOUTより前へ戻すと、ファイルは空にならず`AB\r\n`の4バイトを保持した。最初のOUT前では新しく開き直さず、直前の実行の内容がCloseで保存される。外部ファイルが常に過去の状態へ復元される仕様ではない。【U/E/S】

時間実行、STEP粒度変更、レジスタ・メモリ手動編集、初期化しないロードモードをまたぐ巻き戻しは追加試験が必要。追跡条件と証拠は [追加解析](WCASL2_FOLLOWUP_ANALYSIS.md) を参照。

### 8.7 レジスタ・値の手動入力

GR値設定はGR0–GR7を選び、CASL定数相当の値を入力する。案内は、16進は `#11FF` のような4桁、文字は `'A'`、10進は `-3` のように指定するという内容。【S】

GR入力経路の16進パースは小文字a–fも分岐上は受け付ける。DCの16進検査とは異なる。文字定数経路は最初のデータバイトを符号拡張する。10進経路は先頭チェック後にatoi相当を使い、厳密なDCの数値検査と同一ではない。【S】

「値の入力」ダイアログでは `#` を付けず16進だけを入力する。どの画面箇所のクリックから開くか、すべてのヒット領域と境界入力は未網羅。

## 9. メイクファイル

複数のCASLファイルを登録し、アセンブル・リンクする。登録上限20。先頭ファイルの最初のプログラムがメイン。選択ファイルをメインに設定すると表示名は先頭へ移動するが、3ファイル以上ではパスとの対応に不具合がある。後述を参照。【U/S】

画面には追加、メインに設定、編集、削除、保存、セーブ時に戻す、閉じるがある。ここでの「削除」はリストから除く機能として説明されており、ソースファイル削除とは区別する。

`.cmk` は単なる改行区切りテキストではない。MFCのCArchiveを使い、次の順で保存するコードがある。【S: `0040AB50`】

```text
int32_le ファイル数
CString cmk自身の保存パス（CMakeDoc +0x50）
CString メインCASLファイルのパス（CMakeDoc +0x54）
repeat ファイル数:
    CString CASLファイルのパス（+0xA8側）
    CString 一覧用ファイル名（+0x58側）
```

元の保存ルーチンへ2ファイル分の合成データを与え、81バイトの出力を確認した。短いANSI文字列は1バイトの長さに続いてCP932の本体を保存し、NULを付けない。長い文字列の符号化は解析ノートを参照。

実際のUIで2ファイルを保存し、339バイトの例とメイン変更後343バイトの例を得た。上記フィールドをデコードして元のシリアライザで再生成すると、全バイトが一致した。日本語パスと表示名はCP932だった。メイン変更はリスト順序と+54の両方を更新する。【U/E】

相対パスcmkは同じディレクトリで開いた直後には2/3ファイルともビルド成功した。ただし別フォルダのCASLを開いてから元のcmkへ戻ってビルドするとプロセスが終了した。元ローダーもパスをそのままfopenへ渡すため、cmk基準へ固定した解決ではなくカレントディレクトリ依存と判断できる。【U/S】

記録した絶対パスが欠け、同名のCASLをcmkと同じフォルダに置いた場合も、自動で置き換えずビルド時にプロセスが終了した。再起動直後にも再現した。`004081D0`のローダーはfopenのNULLを検査せずfgetcへ渡す。元呼出コードの失敗プローブでも確認した。Windows例外コード・ダンプは取得していない。【U/E/S】

「保存」ボタンは内部+50の保存先を使う。moved/relative.cmkを開いても、内部にold/project.cmkが残っていると後者へ書き込んだ。文書タイトルの現在パスと、記録された保存先を同一視しない。他の保存メニュー経路は未網羅。【U/S】

3ファイルA/B/CのCをメインにすると、UIと保存表示名はC/A/B、保存パスはC/B/Aになった。表示名は先頭挿入、パス配列は先頭との交換という実装差による。2ファイルでは差が出ない。元の182バイトの保存結果・コード位置・操作条件は [実ファイルとパスの追加解析](WCASL2_NATIVE_IO_AND_PATHS.md) を参照。【U/E/S】

## 10. 保存設定と環境依存

`wcasl-ii`、`baseaddress`、`loadmode`、`intervaltime` の文字列と読込・書込経路がある。最近使用したファイルなど、MFC共通の設定機能も含む。【S】

この環境では `C:\Users\tabos\AppData\Local\VirtualStore\Windows\Wcasl2.INI` に `[wcasl-ii]` の3キーを確認した。baseaddress=32、loadmode=1、intervaltime=1。元コードにもGet/WritePrivateProfile系の経路がある。全OSの固定パスとはせず、実行ファイル名由来のINIとWindowsのリダイレクトを考慮して移行する。今回の保存場所・値は `followup_settings.json` を参照。【S/ファイル実読取】

高DPI環境のCASL画面では、原版の固定配置・文字描画に重なりが出た。これは画面観察の制約であり、文字内容の省略や見切れを機能の欠落と判断しない。移植では論理上の情報・操作と、旧版のDPI不具合の再現を分ける。【U/P】

## 11. 移植時の受け入れ条件

少なくとも次を比較可能にする。

1. 受理・拒否、エラー種別と発生段階。
2. 再配置前機械語、リンク後機械語、ラベル番地、リテラル配置。
3. ロード後のGR/PR/SP/FR、DSと未使用メモリの内容。
4. 各命令のGR/FR/PR/SP、書き換えたメモリ、CALL深さ。
5. 各最小STEPのフェーズ・マイクロステップ・IR/MAR/MDR/実効アドレス。
6. INのバイト列とLEN、OUTの表示バッファ・カーソル、ファイル出力の実バイト。
7. Enter・Backspace・時間実行・停止・指定アドレス・リロードの遷移。
8. 複数プログラム・複数ファイル・同名ローカルラベル・外部公開名。

忠実な挙動を優先する `wcasl2_legacy` と、空行、文字コード、長いシフト量などを改善するモードを分ける案を推奨する。モード名や機能分離は移植側の提案であり、旧版に存在した機能ではない。
