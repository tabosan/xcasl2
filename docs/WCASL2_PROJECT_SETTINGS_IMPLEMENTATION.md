# cmkと設定の実装

更新: 2026-10-27。原版の観測は[詳細互換仕様](WCASL2_COMPATIBILITY_SPEC.md)と[cmkパスの追加解析](WCASL2_NATIVE_IO_AND_PATHS.md)を参照。本書は移植版の操作と実装方針を記す。

## cmkの操作

「cmkを開く」で原版のANSI MFCアーカイブを読み込む。登録ソースをすべてCP932で読めた場合に画面を切り替える。欠損・不正文字コードの場合はパスを含むエラーを表示し、現在の編集内容を保持する。

エクスプローラーの★がメイン。「プロジェクト」メニューの「現在のファイルをメインにする」で先頭へ移す。「CASLファイルを追加…」は複数選択でき、「現在のファイルを登録から除外」は登録だけを外す。上限は20ファイル。選択を切り替えても各ファイルの未保存の編集を保持する。「ファイルを開く」は独立したソースタブの追加になり、cmkの登録は変更しない。

「開いているファイルでcmkを作成」は現在の編集タブを新規プロジェクトとして扱う。未保存ソースは先に「名前を付けて保存」する。「cmkを保存」では登録とメインを保存する。**cmkにソース本文は入らない。編集内容は各casへ別途保存する。** ソースを閉じる際は対象の未保存変更を確認し、終了時には全ソースとプロジェクト登録を確認する。別のcmkを開く際は登録変更を確認し、既存の編集タブは保持する。[複数タブの操作](WORKBENCH_UI.md)も参照。

`examples/project/sample.cmk` を開いてアセンブル・実行すると、main.casのCALLでsub.casの公開名SUBへ分岐し、GR1=7、4命令で正常終了する。これが複数ファイルの最小例。

## 保存形式とリンク

`project.rs` はint32個数、保存先CString、メインCString、個数分のパスCString＋表示名CStringを扱う。CStringはCP932。255未満は1バイト長、65534未満はFF＋16ビット長、それ以上はFF FFFF＋32ビット長。Unicodeアーカイブ、切断、余分な末尾、NUL、不正CP932、20超の個数は明示エラーにする。

採取済み3アーカイブと、原版で表示名がずれた3ファイルのアーカイブを、デコード→エンコードしてバイト一致することを検証した。コーデックは既存の表示名ずれも保持する。UIでは実際のパスから名前を表示し、保存時は整合するペアを書き出す。

リンクは先頭ファイルから順に配置し、最初のプログラムのSTART指定を実行開始番地にする。STARTの公開名だけを共有し、通常ラベルとリテラルはプログラム単位。各ファイルを独立して構文検査するため、他ファイルのENDで不足するENDを補えない。エラーと配置表はファイル名・そのファイル内の行番号を持ち、配置表をクリックすると対応する編集ソースへ移る。

## 原版と意図的に異なるパス処理

- 相対ソースパスは**実際に開いたcmkのフォルダー**が基準。プロセスのカレントディレクトリや、アーカイブ内の旧保存先に依存しない。ドライブ相対・ルート相対は明示エラー。
- UI保存時は現在の明示的な保存先を使い、ソースは絶対パスで保存する。保存先CStringとメインCStringも更新する。相対パスを保ったまま再保存するUIは未実装。
- 実行上のメインは登録の先頭。旧アーカイブ内のメインCStringを理由に暗黙の並べ替えをしない。
- メイン変更はパスと表示名を一緒に移す。原版の配列ずれ、旧保存先への書込み、欠損ソースでのクラッシュを再現しない。
- 装置出力先に登録中のcasやcmkを使うこと、cas保存で別の編集中ソースやcmkを壊すこと、cmk保存でcasや装置ファイルを壊すことを拒否する。同一ファイル検査には既存のファイルID照合を使う。
- 登録を変更すると、依存するシミュレーターを停止して再アセンブル待ちにする。独立したソースのシミュレーターは保持する。登録ソースの右上のプレビューではそのファイルを先頭にリンクし、プロジェクトの「メインをアセンブルして右に開く」では★を先頭にリンクする。

## 設定

「設定」で配置先頭番地（0000〜0BB7）、ロード初期化（FFFF／0000）、時間実行間隔（0〜60000ms）を変更できる。配置・初期化を変えたら再アセンブルする。原版の「初期化しない」は未実装。

STEP粒度、CASL／COMET、GRの「2進のみ」、レジスタ・ラベル共通の10進値の符号付き／符号なし（既定は符号付き）、メモリ表示先頭、時間間隔、入出力装置のパスも変更時に保存する。GRは既定で16進・10進の同時表示。`binary_registers`は既定falseで、旧`decimal`項目は使わない。PR・SPは表示設定にかかわらず16進のみ。符号表示の変更は全シミュレーターに即時反映する。起動時に復元し、ファイル装置は実際のIN／OUTまで開かない。ソース本文・実行中のCPUやメモリ・未保存編集の復元は含めない。

保存先はTauriの`app_config_dir()/settings.json`。Windowsでは通常 `%APPDATA%/dev.xcasl2.desktop/settings.json` で、設定ダイアログに実際のパスを表示する。JSONはUTF-8、version=1。`signed_decimal`は既定trueで、旧JSONでも不足時にtrueを補う。原WCASL2のINIは変更しない。INIの自動移行は実装していない。

`auto_save`（既定false）と`recent_files`（既定空配列）も保存する。「ファイル」の自動保存チェックと最近使用したCASの一覧は起動時および設定変更時に同期する。履歴は最大20件。[操作と自動保存の範囲](WORKBENCH_UI.md)を参照。

`theme`は`light`／`dark`／`system`。既定および旧JSONの不足時は`dark`。設定画面のプルダウンで選択し、画面とネイティブメニューへ即時反映する。`system`はOSのテーマ変更へ追従する。

設定項目の不足は既定値で補う。不正JSON、範囲外、未知バージョンは警告して既定値で起動し、読込みだけで元ファイルを書き換えない。その後ユーザーが設定を変更した場合、元データを同じフォルダーの`settings-invalid-*.json`にコピーしてから保存する。保存エラーは画面へ通知する。

cmk・cas・設定は、同じフォルダーの新規一時ファイルへ全データを書き、sync後に置換する。書込みや置換が失敗した場合は既存ファイルを残し、一時ファイルを片付ける。casの保存形式はCP932＋CRLF。

## 検証

`cargo test -p wcasl2-core --locked --offline` の34テストが通過。追加9本は原版cmkのバイト一致、CString長254/255/65533/65534/65535、全切断位置、不正入力、相対パス、ファイル境界、ローカル名と公開名、メイン・開始ラベル、設定の全項目の保存復元・既存ファイル置換・破損バックアップ・失敗時の一時ファイル削除を検証する。従来のCPU・パイプライン・ファイル装置テストも維持する。

デスクトップ側にも1テストを追加し、設定保存先が書込み不可の場合に装置変更で実行中のCPUを巻き戻さないことを検証した。`cargo test -p xcasl2-desktop --locked --offline` で確認する。コアと合わせて35テスト。TypeScript/Vite、RustのClippy（警告をエラーとして扱う）、Tauriの埋込みEXEビルドも通過。

WindowsのTauri実画面では次を確認した。記録は `analysis/results/implementation-project-settings/gui-verification.json`、実際に保存したcmkは同じフォルダーの `reordered.cmk`。

1. 相対パスの `examples/project/sample.cmk` を読み、6語をリンクし、別ファイルへのCALLでGR1=7・4命令で正常終了。
2. 編集ファイルをsub.casに切り替え、メインへ移し、ネイティブ保存ダイアログからcmk保存。332バイトを独立に解析し、保存先・メイン・パスと表示名の対応が一致。
3. アプリを終了・再起動して保存したcmkを再読込し、sub.casが先頭に復元され、GR1=7・2命令で正常終了。
4. 設定で配置0040・間隔2345msを保存し、COMET表示へ変更。再起動後に間隔・表示が復元され、アセンブル開始番地にも0040が反映。
5. 検証後は配置0020・FFFF初期化・100ms・CASL表示へ戻して保存し、通常終了。

管理サンドボックス内の検証起動ではAppDataへの書込みが拒否されたため、設定保存・再起動の実画面確認は管理サンドボックス外で起動して行った。通常版に管理者権限を要求する実装はない。
