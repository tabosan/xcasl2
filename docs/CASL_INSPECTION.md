# CASLモードのラベル・スタック表示

更新: 2026-10-30。

CASL表示は原版に合わせ、左上にレジスタ、その下にラベル、右上にプログラム、左下にスタックエリア、右下に出力を配置する。プログラムはレジスタとラベルの2段分の高さを使う。メモリ一覧はその下の全幅に表示する。レジスタは縦の一覧で、PR・SPを先頭、GR0〜7をその下に示す。

各表と出力は個別にスクロールできる。狭いタブや低いウィンドウでも位置関係を維持し、シミュレーター全体を縦横にスクロールできる。COMET表示は[左側のCPU図と出力、右側のメモリ・ソース](COMET_LAYOUT.md)を使う。各表示はシミュレータータブの実行中のメモリを読み、STEP、実行、戻り、リロード、タブ切替に追従する。

配置変更後はフロントエンド32本、TypeScript/Vite、Tauri埋込みEXEビルドを通過。Windows実画面で狭い分割タブ・広い単一グループの配置、個別と全体のスクロール、Helloサンプルの正常終了と出力、COMETとの切替を確認した。記録: `analysis/results/casl-layout/gui-verification.json`。

## レジスタ・ラベルの10進表示

CASLのGR0〜7は通常、16進と10進を2列で同時表示する。「2進のみ」をチェックすると、GRは16ビットの2進だけを表示する（FFFF＝`1111 1111 1111 1111`、0001＝`0000 0000 0000 0001`）。PR・SPは常に4桁の16進だけを表示する。チェック状態はタブごとに保持し、最後に選んだ状態を次回作成するシミュレーターの既定値として保存する。旧設定の`decimal`は廃止し、`binary_registers`がない場合は16進・10進の同時表示を使う。

10進値は既定では16ビットの2の補数として表示する（FFFF＝−1、8000＝−32768）。ラベル一覧の10進列も同じ符号設定を使う。「ファイル → 設定 → CASLの10進表示（レジスタ・ラベル）」で「符号付き」「符号なし」を切り替えられる。変更は全シミュレーターのレジスタとラベルに即時反映され、CPU・メモリ・実行位置は変わらない。選択は設定へ保存し、再起動後も使う。旧設定ファイルにこの項目がない場合も符号付きが既定。16進・2進表示には影響しない。

Windows実画面で狭い分割タブの同時表示、2進への切替、STEP後の値更新、PR・SPの16進固定、チェック状態の保存を確認した。フロントエンド33本、設定テスト9本、TypeScript/Vite、Clippy、fmt、Tauriビルドを通過。記録: `analysis/results/register-columns/gui-verification.json`。

## ラベル

「ラベル / 番地 / 16進 / 10進」を表示する。原版のLabelsと同様、DC・DSとリテラルを対象とし、配列や文字列は全語を展開する。継続行は`+1`、`+2`のように先頭からの語オフセットを示す。値はアセンブル時の定数ではなく、現在のメモリ値。STやINで変更されたデータも表示に反映される。

既定の10進値は16ビット符号付き（FFFFは−1、8000は−32768）。共通設定で「符号なし」を選ぶとFFFFは65535、8000は32768となる。ラベル欄の「符号なし10進」チェックボックスは撤去した。レジスタの2進表示にかかわらず、ラベルの16進列と10進列は常に表示する。

別プログラムの同名ラベルを区別するため、先頭行は`MAIN:BUF`のように公開名を併記する。ツールチップにはファイル名・行番号も表示。ラベル名のクリックで対応するソース行へ移動できる。リテラルは定義行がないため、この移動操作の対象外。

## スタックエリア

「番地 / 16進」を1語ずつ表示し、現在のSPの行に`SP ▶`を付ける。初期状態はSP付近の64語をスクロールして確認する形式で、PUSH・POP・CALL・RETに伴うSPの変化へ追従する。POP後も残っているメモリ値はそのまま見える。

「SP追従」で追従を解除・再開できる。先頭番地を0000〜0BB7で指定すると、その番地から最大64語を表示する。物理メモリ終端では残る語数だけ表示する。SPが物理メモリ外なら「範囲外」と示し、無効番地の値を合成しない。

ラベル一覧・スタック一覧とも、直前のSTEP等で変わった値を強調する。追従状態、指定番地、一覧のスクロール位置はシミュレータータブごとに保持する。これらの追加表示設定の再起動後の復元は行わない。符号表示は全タブ共通の設定として保存する。

## 原版の確認と実装

原版のダイアログ5/138にはLabels、Stack Areaと`Label Address Value (HEX DEC)`の見出しがある。ラベル描画0x413AB0付近は語数分を展開し、0x414013〜0x414053は符号設定に応じてゼロ拡張／符号拡張したメモリ値を10進整形する。スタック描画0x414200は連続番地と16進値を読み、SPとの一致を強調する。

今回の検証ソースを原EXEのリンク処理で実行したラベル情報は`analysis/results/casl-inspection/original-symbols.json`。NEGは002Aから3語、BUFは002Dから2語、リテラル=7は002Fの1語。START・命令のラベルは語数0で、データ表示の対象外となる。

Rustの`Image`・`Snapshot`へ表示用の`symbols`を追加した。名前解決用の既存ラベルマップは維持し、表示用にはファイル、公開名、定義行、番地、語数を保持する。CPU命令・メモリ配置・スタック規則の変更はない。

`crates/wcasl2-core/tests/inspection.rs`は配列・リテラル・同名ラベルと、ST・PUSH・POP・リロードのメモリ値を検証する。`tests/inspection.test.mjs`は符号変換、全語展開、ソース行対応、SP追従・固定番地・物理境界を検証する。

Rustワークスペース45本、フロントエンド16本、TypeScript/Vite、Clippy、fmt、Tauri埋込みEXEビルドを通過。Windows実画面で配列全要素、ST後のBUFのFFFF/−1、PUSH後のSP=00B0とFFFF、POP後のSP=00B1と残留値、符号なし65535、CASL/COMET切替後の保持を確認した。検証には専用の設定フォルダーを使い、普段の設定は変更していない。記録は`analysis/results/casl-inspection/gui-verification.json`。
